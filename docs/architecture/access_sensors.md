# 地面站可见性与卫星传感器

## 桌面工作流

1. 在地面站属性中设置 WGS84 位置与最低仰角（默认 0°，允许 0–90°）。
2. 卫星右键 → **插入传感器**。圆锥传感器挂在该卫星下面，可设置名称、视场半角、对地心指向或跟踪地面站。属性应用后生效，关闭不提交草稿。
3. 地面站、卫星或传感器右键 → **可见性分析**。报告左侧明确列出地面站和卫星／传感器两个对象；右键对象预先选中，对端默认首个可用对象。点击对象字段打开统一的“对象选择窗口”，按名称、路径或 ID 搜索，按适用类型选择；传感器显示在父卫星下方。
4. **可见时段 · Access** 输出开始、结束、持续秒数及是否被分析区间截断。生成后在时间轴显示可见区间，双击结果行跳转到开始时刻。
5. **AER · 方位 / 仰角 / 距离** 输出全部采样时刻的 AER、距离变化率、可见标志和传感器离轴角。曲线默认显示仰角，可切换字段、缩放、跳转时刻和导出 PNG；两类表格均可导出 CSV。

传感器属性页显示所属卫星与圆锥截面示意，修改半角时同步显示全视场角；示意不代表地面覆盖范围。指向方式直接切换，只有跟踪模式显示目标地面站；临时切换模式保留目标草稿，目标缺失时要求重新选择，不自动改绑其他站点。窄侧栏可滚动查看设置，底部操作始终可见；插入、应用与取消的含义分别标明，无效输入在页内提示。

跟踪目标也通过“对象选择窗口”选择，仅列出地面站。对象多时在固定高度的列表中搜索和滚动；同名对象可通过路径与 ID 区分。只有确定后才更新字段，取消保留原绑定，随后仍须应用传感器属性才会修改场景。

传感器应用或复制成功后，对象浏览器自动选中新节点并展开其父级；编辑和重命名保留传感器的选择。更新时重新应用当前搜索条件，匹配子传感器时显示其父卫星；不匹配的对象继续隐藏。其他卫星的展开／折叠状态保持不变，失败或取消不替换当前对象树。

生成任一 Access 报告后，二维地图在该对象对满足约束时显示青绿色虚线。连线只是对象地面投影间的关联提示，不代表地面通信路径。三维视图通过统一场景时间联动；本阶段没有三维视锥、视场地面轮廓或三维可见连线。

修改计算输入或打开项目后清除时间轴区间及地图关联，须重新生成。后台报告捕获不可变输入；完成后如果已过期，保留带过期提示的结果供查看，不把它发布到当前场景联动。模板保留稳定 ID；对象被删除时明确报错，不自动替换为父卫星或其他站点。

## 计算契约

- `core::observe_ground_target` 接收同一历元的 Earth/ITRF 目标状态和固定 WGS84 站点位置。完整状态变换保留地球自转速度项，支持二体、J2、J4、HPOP 与原生 TEME 的 SGP4。
- 方位角在当地大地 ENU 坐标系中由北向东，范围 `[0, 2π)`；仰角相对当地水平面；斜距单位 m，距离变化率为相对速度沿视线的投影（远离为正，m/s）。天顶／天底的方位未定义时返回空值，CSV 留空、曲线断开；不以零冒充北向。
- 可见性同时检查站点最低仰角、WGS84 椭球线段遮挡，以及传感器圆锥视场（如果选择传感器）。采用半长轴 6378137 m、扁率 `1/298.257223563`，椭球内的站点仍使用真实高度，因此视线被遮挡。显示时抬高标记不改变分析。
- `ProjectSensor` 的位置等于父卫星位置。圆锥半角范围 `(0, π/2]`；桌面编辑范围 0.001–90°。Nadir 明确定义为对地心，Targeted 为同一历元指向指定站点的理想跟踪。没有姿态机动、转速上限、安装偏移、地形、折射、光行时、天线增益和通信链路预算。
- `core::find_access_intervals` 使用从分析起点对齐的固定网格，并包含精确终点。发现状态变化后，二分细化至默认 1 ms，结果边界取可见一侧。该容限描述**已发现边界的时间括区宽度**，不代表轨道／EOP 的物理精度。短于搜索步长的窗口或间隙可能遗漏；缩小步长并检查收敛。孤立零时长接触不作为窗口。
- 默认桌面步长 1 s；最多 200000 个网格时刻（边界细化额外计算），超限需缩短区间或增大步长。工作在后台，逐次求值检查取消，失败或取消不返回部分结果。AER 同样不读取显示轨迹或插值缓存。
- `runtime::AccessSession` 拥有项目和时间／EOP／Frame Provider 的快照。必须显式提供与项目记录一致的数据，越界历元报错。结果标识为 `geometric-access-wgs84-v1`，记录项目输入、数据锁和时间数据哈希。搜索步长等查询设置保存在结果定义中，不属于项目输入哈希。

## 对象与持久化

文件层 `application::Project.sensors`（Python `ProjectData.sensors`）保存独立稳定 ID、名称、父卫星 ID、半角、指向模式和目标地面站 ID。ID 在卫星、地面站、传感器之间全局唯一；总上限 10000。传感器是分析组件，不额外产生 Scenario 的轨道 Session 或重复的卫星位置标记。

复制卫星同时复制子传感器并生成新 ID；删除卫星同时删除子传感器。传感器可单独重命名、复制和删除。被 Targeted 传感器引用的站点不能直接删除，须先修改指向或删除传感器。无效父对象、目标、非有限半角和重复 ID 均在发布／保存前拒绝。

当前项目 v40 使用 GSTN v2 保存最低仰角、必需的 SNSR v1 保存传感器，并支持报告类型 7（Access）和 8（AER）。开发阶段仅读写当前格式，不从旧文件补默认值；详见[文件布局](project_files.md)。Access 配置可保存为报告模板，计算结果仍按报告契约导出，不写入项目。

## SDK 与 Python

公共入口：`core/propagation/access.hpp`、`runtime/access.hpp` 以及原有 `generate_report`。Python 使用 `project.objects.sensor()` 创建句柄，`sensor.update()` 原子修改视场与指向；`AccessSession`、`AccessSample`、`AccessInterval` 和 `observe_ground_target` 延续原计算接口。文件层的 `ProjectSensor` 与 `SensorPointing` 保留为低层值；新脚本用法见[对象编辑 API](object_editing.md)。

可运行示例见 [access.py](../../examples/python/access.py)。Access／AER 报告的 `object_ids` 必须恰为 `[地面站 ID, 卫星或传感器 ID]`，不接受空列表代表“全部”。

## STK 对照与验证

参考 STK [Access Options](https://help.agi.com/stk/Content/stk/tools-01a.htm) 的采样发现、事件边界收敛与固定步长设置；当前仅实现固定网格，没有 STK 自适应约束采样。参考 [Basic Constraints](https://help.agi.com/stk/12.7.0/Content/stk/constraints-01.htm) 的地面仰角、地球遮挡与视场约束，以及 [Sensor Definition](https://help.agi.com/stk/Content/stk/sn-01.htm) 的 Simple Conic 半角定义。

对比 STK 时应统一轨道模型、时间／EOP、WGS84 站点、最低仰角、地心指向或理想目标跟踪、关闭光行时／折射／地形，并缩小搜索步长检查短事件。此阶段未取得 STK 同配置运行输出，不能声称数值已与 STK 对齐。

自动验证包含圆轨道地平线解析解、圆锥边界解析解、ENU 与距离变化率、端点截断、零长度接触、发现步长限制、取消、数据不匹配、所有权、当前项目往返及非当前格式拒绝。桌面回归检查对象绑定、删除后不改绑、AER 曲线、子对象属性、关闭草稿、保存重开与时间跳转。真实 GPU smoke 沿用[图形验证入口](../development/build.md)，新增传感器与 Access 交互案例。
