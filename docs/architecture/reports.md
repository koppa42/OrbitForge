# 报告与曲线

参考 STK 的模板、数据提供器与对象绑定方式，报告计算使用 OrbitForge 的 Runtime。桌面和 Python 共用同一个生成、格式化和 CSV 导出实现。

## 使用

打开场景后选择“分析 → 报告”。左侧依次设置对象范围、报告类型、时间与采样、显示格式；右侧切换表格与曲线。顶部可收起设置，扩大结果区域。报告使用现有工作区标签，可分屏或弹出。

对象右键菜单打开报告时只绑定右击的对象，并在左侧持续显示对象名称和范围。切换内置报告类型保持对象绑定；不适用的类型不可选。对象增加不会扩大绑定范围，对象删除后生成报错。通过“选择对象…”打开统一的“对象选择窗口”，明确选择全场景或多个对象；加载已经保存的配置会恢复该配置自己的对象范围。

报告类型字段打开独立的“选择报告”窗口，不使用随模板数量增长的下拉列表。窗口支持名称、内容和对象搜索，以及全部 / 内置报告 / 项目模板筛选。列表显示报告名称和输出用途，项目模板同时显示类型与绑定对象，便于区分同名项；旁边按内容说明、输出形式和对象范围分区预览。窄窗口改为上下排列，并保留各布局的分隔位置。不适用的内置报告可查看原因，但不能确认；已删除对象的模板保留原绑定，载入后可修正范围。确认才切换报告，取消或再次选择当前项保留未应用设置和已有结果。同名模板按稳定 ID 区分；窗口打开期间项目更新会同步候选，已删除的模板不能被误选成另一个模板。

右侧工具栏提供刷新（F5）与当前视图的 CSV/PNG 导出；复制和来源信息位于结果菜单。来源在单独详情窗口查看，不占用结果面积。窄分屏通过“编辑设置 / 查看结果”切换，生成成功后显示结果；宽屏同时展示设置和结果，生成操作固定在左侧底部。“模板 → 另存为模板…”复制当前绑定和设置并创建独立 ID；内置模板保持不变。结果表支持多选行、右键复制或 Ctrl+C，复制内容带列标题。屏幕数值用 12 位有效数字便于阅读，悬停、复制和 CSV 保留完整精度；屏幕时间省略无意义的尾随零。

| 模板 | 输出 |
| --- | --- |
| 场景摘要 | 名称、起止时间、时间系统、对象数量、中心天体 |
| 对象摘要 | 稳定 ID、显示名称、类型、传播/固定站模型 |
| 位置与速度 | 对象、历元、GCRF/ITRF、XYZ、Vxyz |
| 地面站坐标 | WGS84 经度、大地纬度、椭球高、ITRF XYZ |
| 经典轨道根数 | 卫星采样状态的 a、e、i、RAAN、近地点幅角、真近点角；固定 GCRF |
| 经纬高 | 卫星/地面站的经度、大地纬度、WGS84 椭球高；固定 ITRF |
| 可见时段 · Access | 站点与卫星／传感器的开始、结束、持续秒数、分析边界截断标志 |
| AER | 方位、仰角、斜距、距离变化率、可见标志、传感器离轴角 |
| 轨道距离与速率 | 卫星的地心距离、总速率、径向/横向速率、航迹倾角；固定 GCRF |

“整个场景”包含以后插入的适用对象；“对象选择窗口”中取消“全部适用对象”后可勾选具体对象。窗口仅列出当前报告适用的类型，支持名称、路径和 ID 搜索；筛选隐藏对象不取消已有勾选。清空选择不等于全场景，至少选择一个有效对象或明确启用全部适用对象后才能确定。重命名不改变绑定，删除对象后保留配置并在生成时报告缺失，避免无提示地产生不完整报告；取消选择窗口不修改原范围。

所有时间序列报告可跟随场景范围或使用场景以内的自定义区间。步长是整数纳秒，包含起点和终点；不整除时额外保留精确终点，最后一段较短。允许单时刻查询。每个对象的行连续排列，顺序采用项目的卫星、地面站顺序。

报告类型旁的“模板”菜单提供保存、更新和删除；选择“保存为模板…”时才输入名称。保存把定义加入当前项目并标记未保存；再保存项目后写入磁盘。项目 v40 保留配置，不保存数据表；开发阶段只读写当前格式，不兼容旧项目版本。取消生成或生成失败保留上次结果；改变查询仍保留上次结果并提示重新生成；仅修改显示单位或时间系统，且查询与场景输入未变时，直接复用已有结果。格式应用失败保留原结果。结果页显示所对应的报告名称，场景输入改变后提示重新生成。双击含历元的行可定位场景时间。

Access / AER 使用明确的地面站与目标对象对，参见[可见性与传感器](access_sensors.md)。Access 输出区间并联动时间轴，不显示区间端点之间的数值折线；AER 输出时间序列与可见标志。

## 曲线与模板操作

左侧固定主操作只有“生成报告”；对象、类型、采样与单位按顺序排列。报告类型旁的模板菜单保存当前选择，使用已保存模板时可原地更新或另存新模板。取消命名不改变项目。模板属于当前项目，保存项目才写入磁盘；界面不再常驻“配置名称”输入框和底部保存按钮。

右侧在“表格 / 曲线”间切换。时间序列报告可选择一个数值字段、对比最多 12 个对象或单独查看对象。曲线对象字段打开统一的“对象选择窗口”，候选 ID 与名称取自本次结果；场景之后的重命名或删除不会改变旧结果。超过 12 个时选择单个对象查看，完整数据仍保留在表格和 CSV。图例最多两行，其余对象可通过选择窗口和悬停识别。静态摘要不显示时间曲线。视图、字段、对象选择和缩放复用同一不可变结果，不触发传播；修改左侧采样或显示单位仍须重新生成。

曲线支持滚轮缩放、拖动框选时段、右键/Home 还原、方向键平移及双击附近采样点定位场景时间；悬停显示原始样本的精确时间和值。横轴以报告起点为零，自动使用秒、分钟或小时，明确标示起点及 UTC/TAI/TT。经度与周期性轨道角跨越半周时断线。绘图按横向像素保留首尾及极值点，避免降采样抹去单点尖峰；这只影响绘图，不改变表格。连线是离散样本的视觉连接，不是新增计算值。

图表页导出 PNG（2 倍分辨率）或从结果菜单复制图片；表格页导出 CSV、复制选中行。图片包含字段、单位、图例和时间起点，采用当前缩放范围；文件选择器负责覆盖确认，PNG 通过 QSaveFile 原子替换。图形的视图状态和 PNG 不写入项目，当前模板保存的是查询定义。

## 计算与数据一致性

Application 提供 `ReportQuery`、`ReportTemplate` 和组合两者的 `ReportDefinition`，以及共享字段定义 `report_columns(kind)`。Results 提供不可变共享存储的 `Table`（列 ID、名称、基础单位和有类型单元格）。桌面、Python 和 C++ 项目 API 通过 `Analysis::report()` 使用已准备的 Session 与共享表格引擎；低层 `ReportContext` / `generate_report` 仍作为适配入口。报告不读取显示轨迹 `StateTrack`，地图插值不影响结果；轨道步长只在启用 HPOP 固定星历输出时参与科学计算，报告查询的采样间隔仍独立。卫星和地面站的跨参考系计算使用完整状态变换，包含地球旋转引起的速度。

桌面每次生成前检查当前数据是否覆盖完整场景，以及数据身份/外推策略是否与已确认场景一致。变化时沿用场景的数据确认流程：取消则不生成；同意后先重建场景，成功后自动继续报告。一次报告捕获项目、时间/EOP Provider 的共享不可变版本，下载或后续场景编辑不改变运行中的输入。覆盖不足或 UTC 过期不会静默外推；有限 EOP 外推仍由数据中心控制。

桌面将预检查返回的项目值与已加载 Provider 交给后台，通过 `Project::from_data()`、`prepare()` 和 `Analysis::report()` 完成计算，准备步骤不会自动接受额外的数据变化。预检查返回时核对当前输入；生成期间输入或数据变化会取消任务，并通过递增代数阻止旧结果发布，即使输入随后改回原值也不会恢复该任务。失败、取消和过期结果保留上次表格。播放时间、报告模板和纯图形设置不使正在生成的结果失效。结果发布同时保留其 `Analysis`，地图与时间轴的可见性会话复用这份分析的对象和 Provider。

结果记录捕获文档的修订、输入 SHA-256、场景数据锁、UTC 数据 SHA-256 和 `builtin-reports-v2` 算法标识。输入哈希使用规范项目编码，排除报告配置、播放时间和纯图形设置，保留物理输入、对象名称和数据身份；HPOP 固定星历输出启用时保留轨道步长，否则将其排除。该哈希用于识别变化，不是结果缓存键或来源签名。桌面尚未将整个工作台的编辑流程迁入统一文档，因此报告修订来自本次捕获文档；任务是否过期还由界面的输入代数和资源身份校验。

后台任务每批最多 512 个样本，支持进度与取消；桌面表格按需格式化。单次最多 **200000 行**，生成前检查上限；超限应增大步长、缩短区间或减少对象。结果仍驻留内存，尚未实现磁盘分页和无限量导出。

根数调用现有 CSPICE 状态转根数实现；J2 输出是采样状态换算的瞬时根数，不是模型输入的平均根数。圆/赤道轨道采用 Provider 的奇异角约定，抛物线或数值病态情况明确报错，不伪造数值。经纬高使用 ERFA `eraGc2gd` 的 WGS84 转换，卫星先通过已确认 EOP 转到 ITRF；椭球高不是离地高度。速率中径向向外为正，横向速率非负，航迹倾角为 `atan2(径向速率, 横向速率)`。

## 单位与 CSV

内部数值始终使用 m、m/s、rad 和 TAI 整数纳秒；工程格式使用 km、km/s、度。UTC 文本保留闰秒，TAI/TT 不带 UTC 的 `Z` 标记，列头明确时间系统。数值格式化采用经典区域设置与 17 位有效数字；时间保留 9 位小数。

CSV 使用 UTF-8 BOM、逗号分隔、双引号转义和 CRLF 行结束符，支持中文、逗号、引号和名称内换行。先写入同目录临时文件，成功后原子发布；默认不覆盖，桌面覆盖须通过文件选择器确认。取消/发布前失败保留旧文件。CSV 只包含表格，不插入哈希前言；本次溯源信息可在来源窗口和 Python 结果对象中读取，暂不自动导出元数据附属文件。

## 查询与呈现

`ReportQuery` 只描述查询类型、对象范围、区间、步长和参考系；`ReportTemplate` 描述显示列、顺序、逐列单位/标题及默认单位和时间系统。`ReportDefinition{id, name, query, format}` 用于保存配置。Python、C++ 和桌面使用同一套字段定义、校验与文件结构。空对象集合不再隐含全选；普通查询需绑定对象，或显式使用 `ReportScope::all_compatible`（Python `of.reports.ALL`）。全选始终在捕获的分析/项目范围内生效。

生成时保留完整原始 SI 表。`ReportResult::with_template()` / Python `Template.apply()` 返回新呈现，可以重新显示先前隐藏的字段；不创建传播器、不读取数据文件、不重新采样。单元格数值仍是 SI，历元仍为精确 `Epoch`；显示值通过 `numeric_value()`、`cell_text()`、CSV 和绘图一致转换。单位覆盖只影响对应列；场景摘要的起止时刻也保留类型，可重新选择时间系统。实际显示 UTC 时才检查已捕获的 UTC 数据；不含时间列的表不因默认 UTC 而强制加载数据。

桌面现有单位和时间系统控件可以立即应用；保存的自定义列在加载、生成和再次保存时保留。绘图按字段 ID 寻找对象与时间，缺少 `object.id`、`object.name`、`time.epoch` 或数值列时不可绘图，表格和 CSV 仍可用。可见性时间轴使用完整原始区间，不受显示列影响。桌面暂未新增自由选列编辑器。

## Python

```python
import orbitforge as of
from orbitforge import units as u

# analysis 已由 project.prepare() 捕获，satellite 为项目对象句柄。
template = of.reports.Template([
    "time.epoch",
    of.reports.Column("state.x", unit="km", title="X"),
    of.reports.Column("state.vx", unit="m/s"),
])
result = analysis.report(of.ReportKind.CARTESIAN_STATE, objects=satellite,
                         step=u.s(30), template=template)
result.export_csv("state.csv")
# 恢复完整字段并改成 SI，不重新计算。
si = of.reports.Template(units=of.ReportUnits.SI).apply(result)
print(si.numeric_value(0, 4))
project.set_reports([result.definition])
project.save("mission.orbitforge")
```

省略模板仍可使用 `units=`、`time_scale=` 便利参数；提供模板时两者须写入模板，避免重复配置。Python 默认工程单位与 TAI，`columns=None` 使用完整字段，显式空列表报错。`of.reports.fields(kind)` 返回字段 ID、默认标题和原始维度。`Template` / `Column` 为不可变配置值，`Template.apply()` 目前接受 `ReportResult`，其他类型结果继续使用各自的导出/数组方法。保存配置通过 `project.set_reports()` 整体校验并提交，读取可用 `project.to_data().reports` 副本。完整可运行示例见 [report_templates.py](../../examples/python/report_templates.py)。

## C++

```cpp
namespace app = orbitforge::application;
app::ReportQuery query;
query.kind = app::ReportKind::aer;
query.object_ids = {station.id(), sensor.id()};
query.step_nanoseconds = 10'000'000'000;
app::ReportTemplate format;
format.time_scale = app::ReportTimeScale::tai;
format.columns = {{"time.epoch", "TAI", ""}, {"aer.range", "km", "Slant range"}};
auto report = analysis.report(query, format);
auto full = report.with_template(app::ReportTemplate{.time_scale = app::ReportTimeScale::tai});
```

C++ 的原生模板默认 UTC；无 UTC 数据时显式选 TAI/TT。独立 `generate_report(context, definition)` 与 `Analysis::report(query, format)` 共用引擎；前者从捕获项目创建会话，后者复用准备好的会话。Python 原生绑定在释放 GIL 前复制输入配置；结果返回拥有完整来源的不可变表和配置副本。

STK 的报告内容允许选择数据提供器、重排字段、划分具有不同时间依赖的节，并分别设置单位和统计。对应到 OrbitForge，下一阶段应把“查询字段/区间”和“显示样式”分离；时间序列与 Access 区间需要不同结果结构，避免把区间强行展开成采样行。[内容与统计](https://help.agi.com/stk/Content/stk/report-06.htm)

STK 在结果窗口提供刷新、复制、查找、单位及导出设置。当前已提供对象入口、配置副本与表格复制，后续优先完善结果内的格式调整。仍使用简单默认 CSV，需要排版的报告另走文档导出。[结果操作](https://help.agi.com/stk/Content/stk/report_export.htm)

### 界面调整采用的取舍

STK 的报告管理器把对象类型/对象列表、Styles、Time Properties 和 Generate 分区组织，先选对象再选适用样式；报告生成后在结果窗口提供操作工具栏。它不是左侧设置、右侧实时结果的布局。[管理器与对象范围](https://help.agi.com/stk/Content/stk/report.htm)、[官方界面教程](https://help.agi.com/stk/content/training/L1_AccessReports.htm)

OrbitForge 采用左侧设置、右侧结果的布局，借用其对象优先、适用类型筛选、结果工具栏三个特点。报告选择放在独立的可搜索窗口中，区分内置报告和项目模板，主面板只显示当前选择。时间默认使用场景时段，只有选择自定义时段才展开两个时间输入框。配置管理与来源详情保留明确入口，不占用主结果区域。
