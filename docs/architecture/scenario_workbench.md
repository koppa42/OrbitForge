# 场景与属性工作流

基本操作顺序为：**创建 Scenario → 插入对象 → 编辑对象属性 → 播放与检查**。卫星可使用二体、J2 / J4 长期项、SGP4 及 HPOP 数值传播器；固定 WGS84 地面站可与卫星及其传感器进行 Access 分析。HPOP 的力模型和积分设置见[传播器](propagators.md)。

## 桌面操作

插入窗口现提供“卫星”和“地面站”。地面站属性包含名称、经度、纬度和椭球高，默认位置为 0°、0°、0 m；采用青绿色菱形，与卫星共用对象操作和视图选择。坐标、显示间距及 SDK 约定见[地面站](ground_stations.md)。下述轨道及传播器设置只适用于卫星。

对象菜单及右键支持重命名、复制、删除；“数据 → 数据中心”列出数据类型、获取时间、有效期和下载 / 导入操作。数据中心采用左侧列表、右侧详情，可设置有限 EOP 外推及天数。场景打开或重新计算先检查当前数据与实际使用的策略，有变化须用户确认；拒绝则保留原场景，覆盖不足提供数据中心入口。快捷键与稳定 ID 见[对象管理](object_data_management.md)，目录及自动更新见[数据中心](data_center.md)。

1. 启动默认显示场景入口，不自动创建卫星。点击“新建场景”输入名称和分析起止时间。默认 **UTC 当天 00:00:00 至次日 00:00:00**；使用运行时 UTC 日期，不受主机本地时区影响。日期、时间和时间标准合并为一个完整输入框，例如 `2026-10-09 00:00:00 UTC`，可直接输入或粘贴；日历图标展开日期、时分秒和时间标准。弹层中切换 UTC / TAI / TT 保持同一物理时刻，修改文本则按所写的时间标准解释。取消不会创建场景。
2. 新场景只有场景根节点和地球。通过“插入 → 插入对象”（`Ctrl+Shift+I`）、对象浏览器搜索框旁的“+”按钮或对象树右键打开独立的插入窗口。左侧按类别列出对象，右侧选择插入方式；当前提供“场景对象 → 卫星 / 地面站”。默认“定义属性”，点击“配置属性”后在主工作区打开属性草稿；选择“使用默认参数”并点击“直接插入”，会以自动编号的名称创建二体卫星，历元和分析时段继承场景，轨道步长为 60 s，默认显示一圈轨迹。直接插入失败时打开属性页显示错误，保留原场景。关闭或 Esc 取消选择不创建对象，也不改变已有属性草稿；创建场景前插入命令不可用。
3. 选择定义属性后，输入对象 ID、初始历元与状态，点击“插入卫星”才加入场景。二体支持 GCRF、ITRF 位置/速度，以及 GCRF 经典瞬时根数（a、e、i、Ω、ω、ν）。切换参考系自动换算位置和速度，含地球旋转的速度项；选择 ITRF 自动切换到 Cartesian，选择根数自动转回 GCRF。μ 由中心天体提供，卫星属性不再有“更多参数”或独立 μ 输入框。根数默认使用 km、度，点击单位可换算；公共 API 使用 m、弧度。可重复插入多颗卫星；重复 ID 被拒绝，分析时段继承 Scenario。
4. 场景树右键“属性”或双击对象，默认在主工作区标签页中打开属性。属性页导航随宽度变化：宽时为左侧树，检查器宽度（400–680 px）为顶部页签，更窄时为下拉选择。二维、三维主视图与属性都是可拖动、可关闭的页面；切换标签保留未应用输入，标签栏右侧按钮可将当前页弹出或放回工作区。场景属性与卫星属性分别保有页面，卫星编辑器一次编辑一个对象。重新从对象树打开对象会装入已应用值；单击其他对象只改变选择，编辑目标仍以标签标题为准。
5. 修改轨道或外观后点击各页的应用按钮生效；关闭面板不会自动提交草稿。异步更新期间仍可播放当前已发布结果；计算取消或输入/资源错误保留原对象。更新期间暂停新建、插入和切换属性目标，避免提交到错误对象。
6. 默认卫星是点标记。已插入卫星可选择内置模型或本地 `.glb/.gltf/.vsgb/.vsgt` 模型，并配置示意显示直径。尺寸按包围盒归一，朝向固定于 ITRF；两者仅用于显示。
7. 拖动二维、三维或属性标签到页面左、右、上、下边缘形成分屏；拖到另一个标签栏合并，在标签栏内拖动调整顺序。拖出主工作区可独立显示，拖动中按 Esc 取消；分隔条可调整各组比例，标签右键也提供分屏、合并和弹出操作。关闭二维或三维页后，通过“视图”菜单或快捷键重新打开；相机、地图缩放与当前时间保持不变，页面移动不触发轨道传播。
8. 二维、三维和对象树共用选择与时间轴。各视图工具栏提供适配、定位所选对象和缩放，显示设置收进右侧菜单。二维支持星下点、地面轨迹、经纬网、昼夜分界和太阳直射点；滚轮缩放、拖动平移，双击或 Home 复位，指针悬停显示经纬度。点击星下点选择同一卫星，点击空白处取消选择。仅打开二维时播放和时间跳转继续工作。

正常启动只显示启动画面与主工作台；初始化子控件时不得短暂显示独立窗口。需要设置可见性的子控件先指定父控件，再设置显示状态；回归测试记录构造期间的顶层窗口显示事件，不能只检查构造完成后的可见状态。

启动页以卡片提供“新建场景”“打开项目”和“二体示例”三个入口。标题栏左侧为菜单，右侧以图标提供新建、打开、保存、“报告”和“数据中心”；右侧场景标签以状态点区分未创建、当前场景和 EOP 外推。场景菜单及工具栏支持 `.orbitforge` 文件的打开、保存和另存为；保存已应用的场景设置、对象输入、对象显示设置、当前时刻和数据版本引用，未应用的属性草稿不自动提交。新建、打开和退出前可保存、放弃或取消未保存的更改。打开失败保留原场景。格式、Python 互通与资源依赖见[项目文件](project_files.md)。

桌面采用靛蓝灰底色、取自启动插画的星蓝色主操作与少量樱粉点缀，按桌面工具的密度设计：12 px 正文、统一 28 px 高的单行输入（下拉框、文本框、带单位数值、历元）、24 px 的列表行；边距与间距取自 `theme::space` 的 4 px 网格。各区域（标题栏、对象浏览器、工作区、时间轴）是浮在深色底上的圆角面板，间隔 6 px，控件均为扁平样式：以底色深浅和 1 px 细线区分层次，不用渐变或立体边；面板标题与工作区页签以色块表示当前项。属性页、场景设置、地面站、HPOP 和数据中心设置等表单共用 `form_kit.hpp`：以“标题 + 细线”的平铺分组排列，不套卡片；同一页的标签列等宽，字段右缘对齐；补充说明收在分组标题旁的说明标记中（悬停或点击查看），页面只保留限制与必要状态；启用整个模型或显示项的选项画成开关。颜色集中定义在 `apps/desktop/src/viewer/workbench_theme.hpp`：样式表以 `@令牌` 或 `@令牌/不透明度` 引用，引用未知令牌时启动即报错；自绘控件（时间轴、启动画面、选择列表等）使用同一组常量。应用使用深色配色方案，Windows 标题栏随之为深色。正文与次要文字在各层底色上保持至少 4.5:1 的对比度，主按钮为深星蓝底白字。樱粉只用于品牌、当前场景状态点、二维 / 三维中的选中标记、对象传播区间、脉冲机动和对话框页签下划线；时间轴与列表的区间条以半透明填充加前缀色带表示，当前项以星蓝浅底加左侧色带表示。属性页提交按钮统一为“应用”，悬停提示与无障碍名称说明具体作用；每页只有一个“应用”，三维视图页的“应用”同时提交空间轨迹开关与卫星外观，外观未变化时不重建模型。带单位的输入框按单位按钮自身字体计算宽度，完整显示最长的可选单位。欢迎页插画铺满页面，左侧以底色渐隐承载标题和三个入口；窄窗口整体加深并在空间不足时滚动，三个入口均支持键盘操作。

启动画面、欢迎页和数据中心分别使用同一银紫粉渐变发色角色的湖畔星夜、轨道观测与观测站插画，均为内嵌静态资源；文字由 Qt 绘制。欢迎页沿用铺满页面的响应式布局，数据中心横幅保留完整人物头部，窄窗口只裁切插画左侧。

### 修改已有场景

双击场景树根节点，或在选中场景后打开属性，可修改场景名称、开始时间和结束时间。日期输入支持 UTC / TAI / TT 和纳秒精度，时长随输入显示；“重置”恢复已应用值。只改名称立即更新场景树、标题和时间轴，不重算轨道或中断播放；设置没有变化时不产生新修订或未保存标记。

修改分析时段会统一调整所有卫星的分析范围，保留稳定 ID、显示名称、初始历元、轨道状态、传播器、轨道步长、轨迹和模型设置。卫星初始历元可以在分析范围之外，不把它自动移到新的开始时间。当前时刻仍在新范围内时保留，否则定位到最近的端点。

应用前检查新时段的数据覆盖；数据或实际外推策略变化时先请求确认。后台使用确认的同一 Provider 准备全部轨迹及模型，完成后一起发布场景、二维/三维显示和时间轴，并标记未保存。准备期间可在状态栏取消，表单禁用重复提交；覆盖不足、拒绝更换数据、准备失败或取消都保留原场景与文件。失败后保留属性草稿供修正。单纯修改时段不增加卫星数值 Session 的输入修订，但增加场景修订；时间轴重置为新的完整范围。

传播器下拉框可选择二体或 J2，旁边“模型…”只读显示传播模型、中心天体常数和传播参考系；J2 额外显示参考半径、J2 系数和计入的长期项。桌面 J2 始终同时计入升交点赤经、近地点幅角和平近点角的长期修正，不提供单项开关，也不保存隐藏的关闭选项。“轨道步长”仅在轨道页设置，默认 60 s；它是输出采样间隔，解析传播器没有数值积分步长或容差。查看或关闭模型信息不会修改或提交属性草稿，点击“插入卫星”或“应用”才发布新的 Session。

J2 输入明确标作“初始平均椭圆”：根数使用平近点角 M，位置/速度表示该平均椭圆的辅助开普勒状态，也可通过完整 GCRF↔ITRF 状态变换输入。它不是实际瞬时状态到平均根数的反演。切换二体/J2 时保留当前椭圆并提示定义改变，不隐含周期项转换。J2 输出速度包含椭圆进动及平近点角修正，与其位置轨迹导数一致。支持参考面外的闭合椭圆，不含周期项、阻力、第三体或 HPOP；模型、常数、验证边界见 [J2 模型与接口契约](j2.md)。

## 统一交互约定

- 炭灰底板、低饱和蓝灰强调、细边框、紧凑布局、统一字体和自绘矢量图标；日期/时间采用整块输入与按需弹出的选择面板。
- 对象树单击负责选择，双击负责属性，右键提供上下文操作。所有入口复用同一命令。
- 默认单一主视图，辅助视图按需打开。时间轴属于场景，默认仅显示场景分析区间；“时间 → 显示所选卫星区间”可按需展开一行卫星传播区间，不给每颗卫星常驻一行。
- 属性左侧为可折叠分组树：“基本 → 轨道、轨迹范围”“二维视图 → 显示”“三维视图 → 显示与模型”。插入卫星前仅开放轨道页。参数按“传播设置”和“初始状态”分两栏，数值与可点击的单位选择器组成完整输入框，统一移除上下按钮，保留键盘微调和校验。页面保留字段、单位、必要状态及错误；补充说明放在分组说明标记或相关控件的悬停提示，自定义时长仅在选择自定义范围后显示。轨迹页分“线条样式”和“显示范围”两组，二维、三维页的显示项为开关。
- 完整时间框支持最多9位小数秒、有效 UTC 闰秒 `23:59:60`；弹层的时、分、秒输入保留上下调节按钮，单击分别增减1小时、1分钟、1秒，长按连续调节，也可直接输入毫秒。只打开、切换时间标准及确认不会丢失原始纳秒。直接粘贴的 TAI / TT 标准在重新绑定时保留；TAI/TT 不接受闰秒60。Escape 或点击弹层外取消草稿，确定后才更新完整输入框。默认一天按 UTC 日历次日计算，闰秒日可为86401秒。
- 创建按钮为新建场景面板的默认动作。卫星属性内容最小宽910逻辑像素，分屏后空间不足时滚动；轨道双栏表单最大宽800，数值与单位组合框最大宽276，历元框最大宽380逻辑像素，随显示缩放适配。大窗口将余量留在表单右侧，单位紧跟数值；场景名称、轨迹范围及模型参数也设置宽度上限。弹出与放回使用同一份输入控件，不重建草稿。关闭属性仅关闭该页面。
- 参考 STK 的场景先行、对象浏览器、分类属性页、全局时间控制，不复制其图标或资源。[STK 场景教程](https://help.agi.com/stk/12.10.0/Content/training/L1_BuildScenarios.htm)、[对象浏览器](https://help.agi.com/stk/Content/gettingstarted/GetStart_ObjectBrowser.htm)、[对象属性](https://help.agi.com/stk/content/stk/ObjectProperties.htm)、[时间轴](https://help.agi.com/stk/content/gettingstarted/GetStart_7_TimelineView.htm)。

### 带单位的数值输入

桌面组件 `QuantityEditor` 位于 `apps/desktop/src/viewer/quantity_editor.hpp`。点击框内右侧单位，只列出同一物理量的可选单位；选择后换算左侧数值，保持物理量不变。读取时显式指定目标单位，不依赖当前显示单位，也不需要调用者再乘换算系数。

| 物理量 | 可选单位 | 使用位置 |
| --- | --- | --- |
| 角度 | °、rad | 倾角、升交点赤经、近地点幅角、真近点角 |
| 长度 | m、km | 位置、半长轴、模型示意直径 |
| 速度 | m/s、km/s | Cartesian 速度 |
| 时长 | ms、s、min、h、d | 轨道步长、轨迹前后时长 |
| 引力参数 | m³/s²、km³/s² | 通用控件支持；卫星 μ 从中心天体读取 |

```cpp
using orbitforge::desktop::QuantityEditor;
using orbitforge::desktop::Unit;

QuantityEditor angle(Unit::degree);
angle.set_value(180, Unit::degree);
angle.set_unit(Unit::radian);             // 显示约 3.14159265358979 rad
const double radians = angle.value(Unit::radian);
const double degrees = angle.value(Unit::degree); // 180，与显示单位无关
```

组件以 SI 值保存未编辑的物理量；显示采用15位有效数字，反复切换单位不会把显示舍入写回存储。文本输入使用小数点并支持科学计数法。无效或未完成的输入保留原文并标记错误，读取及换单位会拒绝该输入；不同物理量之间的单位转换同样被拒绝。偏心率无量纲，不显示单位菜单。

`set_range(min, max, unit)`、`set_single_step(step, unit)` 和 `set_quantum(quantum, unit)` 都按明确单位定义物理约束。轨道步长继续限定为1–60整数秒，例如 `0.75 min` 等于45秒，`0.751 min` 被拒绝。键盘上下键的物理增量不随显示单位改变。这里的 `d` 是86400秒时长，不用于替代 UTC 日历的“次日”。

`valueChanged` 只报告有效物理值的变化，参数是 SI 值；纯单位切换只触发 `unitChanged`。重新绑定参数时保留当前控件的单位选择；此选择目前不跨程序重启保存。单位切换不自动传播轨道，仍由应用按钮提交。公共计算 API 与 Python 保持原有 SI 约定，桌面适配器按明确单位读取；现有显示设置中分钟和千米字段的存储格式保持不变。

## 公共 API 与发布边界

`Application::Scenario(name, first, last)` 初始没有对象，要求非空名称和正向时间区间。`with_object(session)` 返回新场景值；新 ID 从修订 1 开始，替换只接受该 ID 的下一修订，旧版本继续可读。`sample(epochs)` 先检查所有历元均在场景区间内，再调用各 Session。Python 暴露同一实现，没有 Qt 依赖。

`Scenario.with_settings(name, first, last)` 返回新的场景值，保留数值 Session 和数据引用；调用者负责在发布前检查外部数据覆盖。`Project.with_settings(name, first, last)` 同步全部对象分析范围并限制当前时刻，检查所附 EOP 数据是否覆盖新范围；如需换数据，调用者先显式设置新的 `earth_orientation`。两者均不修改旧值，不改变轨道初始历元或初始状态。

桌面先在后台准备候选 Session 及当前显示范围的 GCRF、ITRF Hermite 缓存，再通过 GPU 编译屏障安装轨迹；成功后同时发布场景修订和对象。每个卫星各有轨迹、模型宿主与显示设置。后续移动显示缓存不会递增 Session 或场景修订。显示缓存不作为后续 Access 分析的数据源。

Python 内存场景示例见 `examples/python/two_body_scenario.py`，项目文件示例见 `examples/python/save_project.py`。`Application::Project` 保存可序列化输入，Runtime 从该输入重建不可变 Scenario；当前未实现撤销/重做或所有 STK 对象。

### 坐标系与按需显示缓存

三维默认使用地心 **GCRF**，惯性轨迹保持在该坐标系中，地球随场景时刻按 ERFA/IERS 的 GCRF↔ITRF 旋转更新。视图工具栏可切换 ITRF，保持同一时刻和观察方位；相机、轨迹、点标记、模型及 WGS84 遮挡拾取使用一致的坐标转换。二维始终使用 ITRF/WGS84，不随三维坐标选项改变。

轨道步长默认 **60 s**，可设1–60 s。默认显示“一圈轨迹”，按二体初态求周期，围绕当前时刻并限制在场景内；边界处平移范围以保留完整一圈，非闭合轨道改用一小时。显示轨迹首次只准备此范围及15%前后缓冲；HPOP 科学星历则先在后台生成场景内完整滑行段，独立于显示缓存。跳转到未缓存时刻时，当前位置立即由 Session 求值，轨迹在后台补齐；过期请求的结果不发布。播放继续使用已发布数据，失败保留旧缓存并给出状态提示。

“基本 → 轨迹范围”可选择一圈、整个场景时段或自定义前后时长；二维地面轨迹/名称、三维空间轨迹/模型分别设置。已有缓存覆盖所需范围时，仅调整绘制区间；超出时才按需计算。两个视图都隐藏对象轨迹时停止请求新的轨迹缓存。显式选择全时段才准备全时段；之后缩小显示范围可继续复用已有数据。每次缓存最多10001个节点，该限制作用于请求的显示区间。

节点保留完整位置和速度变换，供 Hermite 插值；每段1/4、1/2、3/4位置分别对照直接传播值，GCRF、ITRF抽样误差都必须≤1 m，否则要求减小步长。检查点只求位置旋转，省去不需要的旋转导数。此限值是显示位置插值的抽样检查，既不是轨道物理精度保证，也不代表60 s折线弦段处处误差≤1 m。

### 二维地图的显示约定

二维复用已经发布的 ITRF 状态及轨迹采样，使用 Rocky 的 WGS84 椭球坐标转换得到大地经纬度，按等距圆柱投影显示。它是参考椭球上的显示投影，不包含独立的 ITRF/WGS84 框架实现或新的轨道计算。经度跨越 ±180° 时分割折线，保留沿日期变更线的纬度变化。轨迹候选在三维 GPU 编译与场景提交前准备，成功后一起发布；二维轨迹不作为 Access 分析输入。当前不含二维覆盖区域或其他地图投影。经纬网、轨迹、对象名称与太阳直射点可分别开关。经纬刻度随地图缩放调整；夜侧采用保留海陆纹理的冷蓝乘色与窄边界抗锯齿，避免半透明灰块盖住极区。

二维和三维共用地固太阳方向与场景时刻：ERFA `epv00` 给出日心地球位置，取反归一后以既有 ERFA/IERS 旋转转换到 ITRF。该近似以 TT 代替 TDB，并省略光行时、光行差，仅用于显示光照，限1900–2100年；实际场景仍受所带 EOP/UTC 数据覆盖限制。二维显示的是参考椭球法线与太阳方向决定的几何昼夜边界；抗锯齿不是大气曙暮光或地影分析。太阳直射点使用平行太阳光的法线方向大地经纬度。

三维使用 Rocky 的方向光与大气边缘，夜侧保留弱环境光。关闭“昼夜光照”会同时关闭二维遮罩及三维昼夜/大气显示，并保留模型的环境照明。两视图的明暗曲线适合各自的地图和三维观察用途，不要求像素亮度相同。以上显示效果不作为 Access、日照时长或食区判定依据；未新增物理地影分析。冻结万星基准继续使用原有无贴图、无光照场景。

视图组织参考 [STK 二维图形属性](https://help.agi.com/stk/content/stk/2Dgfxproperties.htm)、[地图交互](https://help.agi.com/stk/content/stk/map.htm)及[三维工具栏](https://help.agi.com/stk/content/vo/votoolbar.htm)。不复制其图标或地图资源。

### 时间轴的浏览与定位

时间轴由紧凑播放控制、全场景总览、详细日历刻度和区间行组成。上方总览始终显示场景完整起止日期，蓝色窗口表示下方的可视范围；琥珀色游标在两层同步标记当前时刻。跨日时显示两端日期，多日刻度补充日期。场景只有一个仿真时刻，卫星、二维和三维共用它。

播放按钮两侧提供“减慢”“加快”，按相邻常用倍率调整。倍率框右侧下拉选择0.1、0.5、1、2、5、10、20、50、100、200、500、1000倍，默认20倍；也可在框内输入0.1–1000之间、最多一位小数的自定义倍率，按 Enter 或离开输入框确认。自定义37.5倍向下切至20倍、向上切至50倍，边界处禁用对应按钮。按钮、下拉菜单及“时间”菜单使用同一倍率，调整时保持播放/暂停状态和当前时间轴浏览范围。

右侧折叠按钮或 Ctrl+J 可收起总览、刻度和区间行，为视图及属性腾出空间；播放、倍率、精确时间输入仍可操作。展开后保留原来的仿真时刻和浏览范围。工作台使用统一的石墨灰面板、冷蓝选中态和线性图标，常用场景命令集中在左上方；视图工具条与工作区标题对齐，属性页合并标题和对象信息，减少重复留白。

- 单击或拖动下方刻度/区间：跳转到对应时刻并暂停播放。定位使用连续 TAI 毫秒，不经原归一化滑块的10000档量化；完整时间输入继续保留更高精度。
- 拖动总览窗口：浏览时间范围；拖动窗口两端：调整可视区间。双击总览或点击“显示全时段”复位。
- 滚轮：以鼠标位置缩放；Shift+拖动或中键拖动：平移；Shift+滚轮：平移。浏览和缩放不改变仿真时刻，也不暂停播放。
- “定位当前时间”将可视窗口移到游标；手动浏览后，播放不会强行改变窗口。游标在范围外时显示方向提示，仍可在总览看到位置。
- 点击右侧当前时间或 Ctrl+T 打开完整时间输入；UTC / TAI / TT 切换只改变表示，不改变物理时刻或可视区间。
- 焦点在时间轴内时，左右键按当前可视跨度微调（最小1毫秒），Home/End 到场景端点，Page Up/Down 平移，+/− 缩放，F 全时段，C 定位游标。

默认收起卫星行，因为当前卫星都继承场景传播时段，重复常驻显示没有额外信息。打开可选行后，仅显示所选对象的真实传播区间；它不引入独立播放时钟，也不表示已经实现 Access 或任务事件。后续独立有效期、Access 窗口及任务事件可按需加入区间行。

可视跨度最小1秒；不足1秒的场景保留自身跨度。日历刻度逐点经过时间服务转换，UTC 闰秒不按固定 TAI−UTC 偏移近似，细刻度能显示 `23:59:60`。指针定位分辨率为毫秒，物理场景边界仍按原始 Epoch 检查。

### 当前日期的数据覆盖

附带 IERS Bulletin A `finals2000A` 快照覆盖 **2026-09-01 00:00 至 2026-11-01 00:00 UTC**，为当前场景提供极移、UT1 和天极偏移，包含明确标记的预测值。历史二体示例仍使用独立的2000年C04验证快照，冻结万星基准不换数据。数据过期不会静默外推，也不会把今天改成历史日期；可在数据中心下载完整 finals 文件，下一次打开或计算场景时检查当前数据，身份或实际外推策略变化须确认后采用。C04、finals2000A 与 UTC 均可完整下载，分别设置自动检查周期；具体选择与默认优先级见[数据中心](data_center.md)。

快照保存原始定宽记录、源文件和子集 SHA-256、来源 URL。Bulletin A 的 dX/dY 原始单位为毫角秒；导入后统一为弧度。五个分量在连续 TAI 上使用相邻割线确定导数的 Hermite 插值，其版本与使用观测率的 C04 插值分开。来源记录中的预测掩码包含插值及导数所依赖的相邻样本，位1=极移、位2=UT1、位4=天极偏移。这些预测不能视作最终 C04 观测值。[IERS 数据源](https://datacenter.iers.org/data/9/finals2000A.all)、[USNO 列定义](https://maia.usno.navy.mil/ser7/readme.finals2000A)。

## 交互与绘制开销

暂停且输入未变化时，复用卫星状态、标记缓冲和时间控件；轨迹传播仍由后台任务按显示范围准备。二维分别缓存底图和轨迹，鼠标悬停只刷新坐标栏。底图缓存覆盖视口及96逻辑像素边距，轨迹精细缓存保留160像素边距；平移时复用图像，经纬刻度和卫星标记独立绘制。昼夜蒙版只有曙暮光边缘执行渐变计算，其余区域直接使用相同的日侧或夜侧常量颜色。

超过1024个路径顶点的轨迹，预览与精细栅格化均在后台完成。先从全部显示路径生成固定2048×1024的全图预览，再生成当前视口、当前设备像素比的精细图像。缩放时优先变换覆盖完整视口且倍率相近的精细缓存，否则使用全图预览；预览可能暂时变软，停止操作后由当前倍率的精细结果替换。首次生成或轨迹内容改变后，预览也要等待后台准备；切换选择只更新标记叠加层，不重新栅格化轨迹。没有抽稀轨迹顶点、更改传播步长或把预览图像用于分析计算。

视口稳定100 ms后，底图、经纬网、轨迹与刻度合成为一张当前视口大小的图像；播放时在其上绘制移动标记和 Access 连线。昼夜、轨迹图像、网格、字体、视口或 DPI 变化均使合成缓存失效。平移及连续缩放期间直接绘制，避免额外合成；等比例图层直接按原生像素尺寸绘制。对象标签按显示文字、字体和 DPI 缓存，容量上限4 MiB，定位到设备像素以保持清晰；缓存不用于任何数值计算。工作台图标复用 Qt 管理的有容量上限的像素缓存。

每张地图最多一个绘图任务。视口、DPI或内容改变后取消不再适用的精细任务，在轨迹内部每256个顶点检查取消状态；全图预览仅在几何或显示范围改变时失效。精细结果发布同时检查内容修订、完整性、倍率和覆盖范围，过期或部分绘图不能覆盖当前图像。密集轨迹的图像分配和线段绘制均在工作线程完成，任务只接收不可变路径和独立取消标志，不读取 QWidget。

新增、编辑或补充一颗卫星的轨迹，只更新对应的二维轨迹并编译对应的三维静态子图，不重建其他对象、渲染任务或交换链。同类图层共享仍在使用的 Vulkan 管线；所有图层关闭后不由全局缓存持有 GPU 对象。替换旧资源前保留 GPU 同步屏障，窗口重建继续使用原来的完整生命周期流程。

`tools/validation/run_workbench_profile.py` 使用正常工作台、全天60秒采样轨迹及合成 Qt 输入，分别记录三维拖动/缩放、二维悬停/平移/缩放、播放和并排播放的 GUI CPU 耗时与帧间隔。缩放后增加静置阶段，断言精细缓存恢复并保存截图。它不等同于屏幕呈现时间或实际设备输入延迟；正确性另外使用 `run_graphics_smoke.py` 和 Vulkan 同步验证检查。测量结果写入 `out/validation/`，不提交生成报告。

## Windows 便携包

```powershell
python tools/packaging/package_windows.py --build-dir out/build/desktop-graphics --dependency-prefix out/dependencies/installed/x64-windows --output out/releases/OrbitForge-0.2.1-win-x64 --reports out/validation/package-new-run --verify --zip
```

输出与报告均须使用新目录，且不能互相包含；公开包的清单仅记录文件与散列，完整 DLL 来源路径保存在本地报告中。整个 ZIP 解压后双击 `OrbitForge.exe`，保留同目录 DLL、`plugins` 和 `resources`。桌面启动不需要 Python 或 Qt SDK，需要支持 Vulkan 的显卡驱动。

验证包括依赖递归解析、文件 SHA-256、ZIP 完整性、删除开发环境搜索路径后的异地目录启动、无参数打开/关闭，以及便携版本完整场景交互检查。这是同一 Windows 主机上的部署验证，不等同于全新虚拟机或所有显卡的兼容性认证。

HPOP 启用固定星历输出时，轨道步长同时控制科学星历节点；关闭时仅控制显示采样。更改前者会使已有分析失效，报告自身采样间隔仍独立。详见[科学插值](orbit_interpolation.md)。
