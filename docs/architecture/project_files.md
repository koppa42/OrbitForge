# OrbitForge 项目文件 v40

`.orbitforge` 是由 Application 模块读写的单文件、分段二进制容器。桌面、Python wheel 和 C++ SDK 使用相同实现。此版本保存可重建场景的输入，不保存 Provider 指针、GPU 资源或显示轨迹缓存。采用独立格式是为了精确保存纳秒整数和浮点输入，并允许以后为结果引用、其他对象和资源增加有版本的段。

## 当前工作流

桌面提供“打开”“保存”“另存为”，快捷键为 Ctrl+O、Ctrl+S、Ctrl+Shift+S。插入对象改用 Ctrl+Shift+I。启动页也可打开项目。保存内容是**已应用**的场景和属性；属性页中尚未应用的草稿不自动提交。场景创建、轨道、对象外观和对象轨迹范围的应用都会标记未保存；新建、打开和退出前可保存、放弃或取消。

保存包含场景名称、起止时刻、保存时的当前时刻，地面站的稳定 ID、显示名称、WGS84 经纬度及椭球高，以及每个卫星的 ID、二体/J2/J4/SGP4/HPOP/任务序列传播器、初始状态、输入参考系、显示步长、二维/三维轨迹和名称选项、轨迹范围、轨迹颜色/线型/线宽、模型类别、尺寸及外部路径。当前时刻写入文件，但播放和浏览时间本身不反复标记项目修改。相机、分屏布局、全局视图开关和未应用草稿属于尚未保存的工作区状态。

场景属性可以修改名称和分析时段；成功应用后保留当前文件路径并标记未保存，普通保存更新磁盘文件。所有卫星继承新分析范围，初始历元及物理输入保持不变；地面站保持坐标不变，当前时刻限制在新范围内。取消或应用失败不改写项目。

打开时先校验文件，在后台重建全部 Session、轨迹和模型，再编译图形资源并整体发布；状态栏可取消打开。当前数据不覆盖分析时段、计算或模型读取失败，以及取消准备时保留当前项目。载入的计算快照从新修订开始，稳定对象 ID 和计算输入保持不变；运行中的任务和修订计数不序列化。

EOP 来源记录包含快照 ID、SHA256、参考系、插值版本、覆盖区间，以及其依赖的时间数据 ID、SHA256 和 UTC 有效期。这些字段描述上次计算，不强制桌面安装同一旧文件。桌面打开或重算先比较当前数据及实际使用的外推策略，不一致时请求确认；同意后重建并标记未保存，取消则不打开或重算。保存时更新来源记录。覆盖不足时提供数据中心入口，保留原场景。通过“数据 → 数据中心”查看数据、获取时间和有效期，导入或下载当前文件，详见[数据中心](data_center.md)。

开发预览阶段只读写当前 **v40**，不维护旧格式兼容、迁移器或缺字段补默认值的读取分支。v1–v38 及未知版本在解析内容前明确拒绝，错误包含实际版本和本程序支持的版本；源文件和当前场景不被修改。需要打开旧项目时使用与该格式匹配的程序，或在当前版本重新创建项目。后续结构或语义变化时递增版本，并同步替换读写实现、测试与文档；不为兼容旧文件限制新 API。

外部三维模型按项目所在目录保存相对路径，跨盘时保留绝对路径；另存为会重新计算路径。模型及其纹理、外部缓冲文件仍需随项目另行保留，当前容器不嵌入资源，也不提供外部模型内容版本校验。模型缺失时拒绝打开，不静默改成点标记。内置示意模型无此文件依赖。

## 二进制约定

所有整数按小端编码，`f64` 是 IEEE-754 binary64 原始位。`epoch` 是自 2000-01-01 12:00:00 TAI 起的有符号 64 位纳秒，以二进制补码保存。字符串为 `u32` 字节长度后跟 UTF-8，无结尾 NUL；拒绝非法 UTF-8 和内嵌 NUL。长度和浮点输入没有文本舍入。

文件头共 24 字节：

| 字段 | 类型 | v40 值或含义 |
| --- | --- | --- |
| magic | 8 bytes | `ORBFPRJ` 后跟 LF，即 `4f 52 42 46 50 52 4a 0a` |
| format_version | u32 | 40（唯一接受的版本） |
| payload_length | u64 | 后续全部段的总字节数 |
| payload_crc32 | u32 | 后续全部段的 CRC-32/ISO-HDLC |

每个段由 `tag:u32, version:u32, length:u64, crc32:u32, body:length bytes` 组成；校验覆盖 body。tag 的四个小端字节直接组成 ASCII 名称。读写器共用一份当前段定义，版本与必需性见下表。必需段即使对象数为零也必须出现一次；可选段最多一次。读取不依赖段顺序，写入顺序固定为 SCNE、OBJS、STYL、GSTN、SNSR、RPTS、可选 DATA、可选 TIME、可选 ANLY、LOCK。非当前文件版本、非当前段版本、未知段、重复段和多余字节均拒绝。

| 段 | 段版本 | 必需 | body 字段顺序 |
| --- | --- | --- | --- |
| SCNE | 1 | 是 | 名称 string；first、last、current 各 epoch；中心天体模型 ID string |
| OBJS | 31 | 是 | 对象数 u32；随后依次为下述卫星记录 |
| STYL | 1 | 是 | 卫星数 u32；随后每条为卫星 ID string、颜色 u32（0xRRGGBB）、线型 u32（0 实线、1 虚线、2 点线、3 点划线）、线宽 f64（0.5–8 逻辑像素）；必须与 OBJS 中卫星一一对应，拒绝未知/重复 ID、非法样式与非有限宽度 |
| GSTN | 2 | 是 | 地面站数 u32；随后每条为 ID string、显示名称 string、经度 f64（rad）、大地纬度 f64（rad）、椭球高 f64（m）；最低仰角 f64（rad） |
| SNSR | 1 | 是 | 传感器数 u32；每条为 ID、名称、父卫星 ID 各 string；圆锥半角 f64（rad）；指向 u32（0 对地心，1 跟踪站点）；目标站点 ID string |
| RPTS | 2 | 是 | 报告数 u32（最多 128）；随后依次为下述报告配置 |
| DATA | 2 | 否 | EOP ID、SHA256、来源 URL、参考系、插值版本各 string；覆盖 first、last 各 epoch；时间数据 ID、SHA256、来源 URL 各 string；UTC 有效 MJD 起点、终点各 u32；外推天数 u32（0 禁止，1–30 为端点线性外推上限） |
| TIME | 1 | 否 | 独立 UTC 数据的 ID、SHA256、来源 URL 各 string；有效 MJD 起点、终点各 u32（非负且起点小于终点，最大为 int32 正值）；EOP 存在时使用 DATA 自带的 UTC 身份，TIME 仅作非活动的独立 UTC 记录 |
| ANLY | 1 | 否 | 准备时的项目物理输入 SHA256 string、数据锁 SHA256 string；均为 64 位小写十六进制；没有此段表示未记录分析准备 |
| LOCK | 1 | 是 | [数据锁规范编码](scenario_data_lock.md)；随后是清单总 SHA-256 string |

卫星记录字段依次为：ID string；显示名称 string（空字符串表示使用 ID）；传播器 u32（1 二体，2 标准一阶 J2 长期项，3 J4 长期项、4 SGP4、5 HPOP、6 任务序列）；编辑参考系 u32（1 GCRF，2 ITRF）；初始历元 epoch；三分量位置和三分量速度各 f64（m、m/s）；轨道步长 u32（1–60 整数秒；显示采样及启用时的 HPOP 固定星历输出网格）；轨迹范围 u32（0 一圈、1 场景、2 自定义）；前后时长各 f64（min）；二维轨迹、二维名称、三维轨迹各 u8 boolean；模型类别 u32（0 点、1 内置、2 外部）；模型尺寸 f64（m）；模型路径 string；TLE line1、line2 各 string（非 SGP4 必须为空）。

报告记录字段依次为：ID string；名称 string；查询类型 u32（0 场景摘要、1 对象摘要、2 位置与速度、3 地面站坐标、4 经典轨道根数、5 经纬高、6 轨道距离与速率、7 可见时段、8 AER）；选择模式 u32（0 指定对象、1 全部适用对象）；绑定对象数 u32（最多 10000）及 ID strings；跟随场景 u8 boolean；自定义 first、last 各 epoch；步长 u64（1–86400000000000 ns）；坐标系 u32（1 GCRF、2 ITRF，仅 Cartesian 查询使用；根数与速率固定 GCRF，经纬高固定 ITRF/WGS84）；默认单位 u32（0 SI、1 工程）；默认时间系统 u32（0 UTC、1 TAI、2 TT）；显示列数 u32（最多 64，0 表示完整默认字段）；每列依次为字段 ID、单位、标题各 string（空单位/标题使用默认值）。

全部适用对象模式必须使用空 ID 集合；指定对象模式在普通报告中必须非空。场景摘要不接受对象 ID；Access/AER 必须使用指定对象模式，恰为地面站 ID、卫星或传感器 ID 两项。字段 ID 必须属于该查询的共用字段定义、不得重复；单位必须与原始维度匹配（m/km、m/s/km/s、rad/deg、epoch 对应 UTC/TAI/TT）。未知字段、选择模式、非法列数及不匹配单位明确拒绝。报告 ID 必须唯一；允许保留已删除对象的绑定或超出新场景范围的自定义区间，生成时明确报错，不妨碍打开项目。生成结果不写入项目，需重新生成或导出 CSV。详见[报告](reports.md)。

二体/J2 的持久化初态均为地心 GCRF，中心天体常数保持 `earth-iers2003-v1`。J4 初态为 EGM2008 平均椭圆的辅助 GCRF 状态；SGP4 以两行 TLE 为唯一轨道输入，initial/frame 字段仅保留非活动的手动输入草稿，不参与 SGP4 计算或报告输入哈希。SGP4 重建时必须显式注入时间 Provider 解释 TLE 历元，详见[预报器](propagators.md)。SCNE 中的模型 ID 表示二体/J2 默认常数，不覆盖 J4 / SGP4 的固定常数。二体初态为瞬时 Cartesian 状态，J2 初态为平均椭圆的辅助 Cartesian 状态；J2 重建时同时启用全部三个长期项。编辑参考系仅用于恢复输入控件的表示，不能把持久化 GCRF 数值解释为 ITRF。模型定义发生不兼容变化时必须变更文件/段版本，同步替换当前读写实现。

读取上限为 64 MiB、10000 个对象（卫星、地面站与传感器合计）、每个字符串 16384 字节、64 个数据引用。检查长度后才分配和读取；拒绝非有限数、重复 ID、不一致的场景区间、非法显示选项及超出数据原始覆盖及记录的有限外推范围的引用。地面站角度与高度按模型支持范围校验。同时检查 LOCK 总哈希及其与活动来源（优先 DATA，否则 TIME，否则空锁，再合并重力、星历、空间天气与海潮引用）的一致性；即使重新计算了 CRC，缺失或不一致的 LOCK 仍拒绝。传感器必须引用存在的卫星，跟踪模式还须引用存在的地面站。轨道物理有效性由 Runtime 在重建 Session 时继续验证。CRC 和 SHA-256 用于完整性与版本核验，不是来源签名或安全认证。

传播器为 6（任务序列）时，在 TLE 字段后先写滑行模型 u32（0 二体、1 HPOP）、段数 u32（1–256），随后每段为类型 u32（0 滑行、1 脉冲）、名称 string。滑行段追加正的 duration i64 纳秒；脉冲段追加方向 u32（0 GCRF、1 VNC、2 LVLH）和三个 Δv f64（m/s）。至少一段滑行，总时长至多 366 天且不得溢出历元；任务范围必须覆盖场景。名称不参与物理输入哈希，段顺序与活动字段参与。

传播器为 5（HPOP），或为 6 且滑行模型选择 HPOP 时，在上述字段之后追加：重力模型选择 ID string（空为内置 EGM96）、所选模型 GM f64（m³/s²）；星历选择 ID string（默认 `de440s`）；按 Sun、Moon、Jupiter、Venus、Saturn、Mars、Mercury、Uranus、Neptune、Pluto 固定顺序保存十条第三体记录。每条依次为启用 u8 boolean、来源 u32（0 Cb file、1 JPL DE、2 User Specified）、手动 GM 存在 u8（存在时追加 SI f64）、Cb 常数存在 u8（存在时追加 SI GM f64、文件名 string、原文 SHA-256 string、天体 u32，0–9 对应上述顺序）；引力 Degree、Order 各 u32；包含引力系数长期变化 u8 boolean；固体潮模式 u32（0 无、1 仅永久潮、2 完整），潮汐截断 u8 boolean；包含附加时间项 u8 boolean；海潮启用 u8 boolean、海潮模型选择 ID string、独立海潮 Degree / Order 各 u32；包含相对论加速度 u8 boolean；卫星质量 f64（kg，有限且正）；积分器 u32（0 RKF78、1 RK4、2 RKV 8(9) Efficient、3 Bulirsch–Stoer、4 Gauss–Jackson 12），VOP 积分开关 u8 boolean（仅 RKF78 / Bulirsch–Stoer 生效，其余方法保留草稿），预测校正方式 u32（0 Full、1 Pseudo；仅 Gauss–Jackson 生效），步长控制 u32（0 Relative Error、1 Fixed；RK4 / Gauss–Jackson 强制固定并保留此草稿），随后七个 f64，依次为相对容差、位置绝对容差（m）、速度绝对容差（m/s）、最小步长（s）、最大步长（s）、固定模式步长（s）、最低地心高度（m）；星历插值方法 u32（0 Lagrange、1 Hermite、2 VOP）、多项式阶数 u32（Lagrange/VOP 0–29，Hermite 奇数 3–29）、VOP μ f64（有限正值，m³/s²）、固定输出星历 u8 boolean；时间正则化启用 u8 boolean、指数 f64（有限且 0<n≤10）、每圈步数 u32（1–2147483647）；随后为 SRP 设置：启用 u8 boolean，阴影模型 u32（0 无、1 圆柱、2 双锥），太阳位置方法 u32（0 True、1 Apparent to True CB、2 Apparent），地球遮挡与月球遮挡、阴影边界缓解各 u8 boolean，以及 Cr、面积质量比（m²/kg）、地球大气等效高度（m）、参考光压（Pa）、参考距离（m）、太阳/地球/月球半径（m）共八个 f64；随后是额外遮挡天体数 u32 及每项的天体枚举 u32、半径 f64（详见下文）。禁用时仍保存有效参数草稿，但这些草稿不进入活动计算身份。其他传播器不写这组字段。HPOP 初值为瞬时状态；重建非中心重力 Session 必须提供覆盖初始历元至场景全区间的 EOP。

文件重力引用以 `gravity/<选择 ID>` 角色写入 LOCK，包含完整原文 SHA-256、归一化解析版本与长期变化物理元数据；读取后恢复为 `Project.force_data`。模型文件由数据中心管理，不嵌入项目，不写本机路径。选中的文件缺失、损坏或 GM 与轨道设置不一致时拒绝准备；内容变化走既有确认流程，允许后再更新引用。

## 卫星轨迹样式

卫星属性 → 基本 → 轨迹显示：提供六种预设色、自定义 RGB 颜色、四种线型、0.5–8 px 粗细与实时预览，点击“应用”后更新视图。颜色同时用于卫星点标记；三维模型的材质保持原定义。二维、三维轨迹共用样式，缩放不改变屏幕线宽，按显示器 DPI 换算。选中对象保留独立的选择标记，线宽不随选择变化。

样式变化仅刷新绘制，不触发物理传播，也不改变报告的计算输入哈希。复制卫星继承样式后可独立修改。Python 通过不可变 `OrbitStyle` 设置，例如 `satellite.display = of.OrbitStyle(line_style=of.LineStyle.DASHED)`；新增卫星在 `project.objects.satellite()` 中传入 `display=`。

## 保存和恢复

先在内存中完成校验与编码，再在目标目录下创建独占临时目录，写入并刷新临时文件，最后原子发布到目标路径。Windows 使用 MoveFileExW，POSIX 使用 rename（覆盖）或 link（不覆盖）。失败会清理本次临时文件；发布前的失败保留已有目标。此处承诺原子替换，不声称对所有网络文件系统或断电场景具备事务持久性保证。

ANLY 的输入哈希采用独立 `orbitforge-analysis-input-v1` 编码：固定分析时段，按稳定 ID 排序记录卫星的活动传播器输入、站点坐标与最低仰角，以及传感器的视场、所属与指向关系。排除名称、外观、播放时间、报告配置及非活动轨道草稿。HPOP 插值方法与阶数参与身份；轨道步长在启用固定星历输出时也是科学输入，否则只影响显示并被排除。ANLY 与当前输入或数据锁不符表示旧准备记录已过期，不是文件损坏；无 ANLY 不推断为已计算。准备记录不包含查询结果，不证明已经执行所有查询。输入项目可以不含准备记录；不因读写而伪造记录。

C++ 文件层保留 `application::Project`、`save_project/load_project`、`runtime::make_project_scenario`。Python `Project`、`load_project` 使用事务门面，对象通过 `project.objects` 管理；显式低层交换使用 `ProjectData`、`load_project_data`，迁移见[对象编辑 API](object_editing.md)。Python `Project.open(path, data=...)` 检查当前数据，变化通过固定的计划确认；`save(path, analysis=...)` 校验项目归属与物理输入，保存精确来源和准备记录，成功后才更新内存。仅读取输入用 `load_project_data()`。详见[分析 API](analysis_api.md)。Python 保存默认拒绝覆盖，传入 `overwrite=True` 才替换已有文件。

```python
from pathlib import Path
import orbitforge as of

project = of.Project("Mission", of.Epoch(0), of.Epoch(7_200_000_000_000))
satellite = project.objects.satellite("Satellite1", orbit=of.orbits.TwoBody(
    initial=of.OrbitInput().initial))
project.save(Path("mission.orbitforge"))

restored = of.load_project("mission.orbitforge")
states = restored.to_scenario().sample([restored.first, restored.last])

# 一次提交项目设置；同步对象分析范围，保留初始条件。
restored.update(name="Mission · revised", first=of.Epoch(1_000_000_000),
                last=of.Epoch(3_600_000_000_000))
restored.save("mission-revised.orbitforge")
```

上述历史时段与桌面附带的 2000 年示例 EOP 匹配。完整双传播器示例见 `examples/python/save_project.py`。HPOP 的非中心重力在无界面计算中也要求显式 EOP；不隐式加载数据或外部模型。

星历引用以 `ephemeris/<选择 ID>` 写入 LOCK，内容哈希为 SPICE 清单 SHA-256（含按序核文件的哈希和覆盖策略），解释哈希含 DE440 牛顿地心位置模型、常数组及 CSPICE 版本。启用天体和实际 GM 进入输入及算法身份；未启用天体的 GM 草稿不改变计算身份。星历文件不嵌入项目；越界不允许通过“接受数据变化”绕过。

Cb 文件只在显式导入时读取引力常数。项目内保存其不可变常数快照及原文哈希，不保存本机路径；重开不依赖原文件。切换来源保留未活动的手动值和 Cb 常数，计算身份只计入当前启用且实际使用的来源。星历仍以 `ephemeris/<选择 ID>` 进入 LOCK，见[第三体引力](third_body_gravity.md)。

HPOP 与 Mission HPOP 在 SRP 参数后保存下节的完整阻力配置。布尔值只接受 0/1，枚举与全部参数按阻力契约校验；合法禁用草稿照常保存。阻力即使使用点质量也记录 UTC/EOP/Sun 的实际来源，见[阻力契约](atmospheric_drag.md)。


## 阻力天气字段

OBJS v31 在光压字段之后写入阻力：启用 u8；Cd、面积质量比各 f64；主密度模型 u32（0 JR、1 NRLMSISE-00）、低空模型 u32（0 无、1 NRLMSISE-00）；拼接范围、手动日 F10.7、平均 F10.7、Kp 各 f64；视太阳 u8；天气选择 ID string（空为手动）；地磁更新率 u32（0 每日、1 三小时、2 三小时保持均值插值、3 三小时自然三次样条）；地磁来源 u32（0 Ap、1 Kp）；近似高度 u8。禁用及非活动字段仍保存合法草稿，实际计算身份由有效选项决定。

文件模式通过 `space-weather/<选择 ID>` 写入 LOCK，保留完整原始文件 SHA-256 和 `spaceweather-utc20-linear-jr-msis-lags-monthly-linear-v2` 解释哈希；FXM 追加日地距离改正约定，CSSI Predicts 追加名义 Ap 与中心 81 日平均约定。不写本机路径，也不嵌入天气文件。接受数据变化只能确认来源更新，不能跳过缺值、历史窗口或覆盖校验。

OBJS v31 在 HPOP 重力 degree/order 之后保存“包含长期变化”u8，然后保存固体潮模式 u32（0 无、1 仅永久潮、2 完整）、“截断至重力场”u8 与“包含附加时间项”u8。完整模式采用 IERS 2003 日月形变，可另启用 71 个频率修正项和固体极潮（2003 原文符号）；全部草稿值保留，0/0 且启用截断时不影响计算身份。随后写入海潮启用 u8、模型 ID string、独立 degree/order 各 u32，再写相对论开关 u8。相对论开关之后保存卫星质量 f64（kg）。质量必须有限且正，与各球形面积质量比的乘积必须可表示；零面积质量比合法。当前球形力仍使用各自显式 A/m，质量只决定对应面积，不计入活动计算身份；质量变化仍作为项目设置保存。仅接受当前格式。


## 海潮字段与依赖

OBJS v31 在三个固体潮字段之后、相对论开关之前保存 `OceanTideOptions`。ID 是 1–64 位小写 ASCII 字母、数字或连字符，不是路径；阶数 0–2190，次数 0–阶数。全部草稿均校验并精确保存；关闭或阶数小于 2 时无海潮力，模型与截断草稿不计入活动输入身份，也不要求文件。活动配置须在准备时符合所选文件实际范围，超出时失败，不静默降低阶次。

活动海潮以 `ocean-tides/<选择 ID>` 加入 LOCK。原始字节 SHA-256、POT 格式解释版本、GM 和半径缩放进入来源，不嵌入文件或本机路径；内容/解释变化沿用确认流程。HPOP 及 Mission 的 HPOP 滑行使用相同字段和依赖。固定 v40 样例独立编码禁用的 `fixture-ocean`、30×12 草稿，C++/Python 必须逐字节复现。详见[海潮契约](ocean_tides.md)。


## 引力系数长期变化

对象保存 `include_secular_variations` 布尔草稿；0/0 时该标志不参与分析和报告输入身份。启用非中心重力时，所选文件必须带显式参考历元与变化率，缺失则准备失败。变化率及参考历元属于冻结的重力资源，随原文字节与解释身份写入 `gravity/<ID>` 引用，不复制到对象字段。没有按模型名猜测的默认历元，也没有旧项目格式兼容路径；详见[长期变化契约](gravity_secular.md)。

固定样例使用 Gauss–Jackson 12（枚举 4）和 Pseudo Correction（枚举 1），保留 0/0 下为 true 的长期变化草稿和未启用阻力的自然三次样条枚举。v40 / OBJS31 样例为 1522 bytes，SHA-256 `fe46dc5ba9f6cc48cb8f56e01e68471f0651a1fb9a1823d145c4355f488f08f5`；插值字段独立编码为 Hermite 5 阶、非活动 VOP μ `4.1e14 m³/s²` 和固定星历输出开启。

### 额外遮挡天体

v40 / OBJS31 在现有 SRP 月球半径之后、阻力字段之前保存额外遮挡天体数 u32（0–8），每项为 ThirdBody 枚举 u32（2–9）和球面半径 f64（m）。Earth/Moon 仍由原有独立字段保存，额外列表不允许 Sun/Moon、未知枚举、重复天体、非正或非有限半径。输入次序作为草稿精确保存，计算身份及阴影求和按枚举次序规范化。禁用光压或无阴影时该列表不进入有效计算身份，且不查询本体星历；合法草稿仍保存。

独立二进制样例包含 Mercury `2440000.125 m`、Venus `6051800 m` 两项禁用草稿，以 `struct.pack("<IIdId", 2, 6, 2440000.125, 3, 6051800)` 插入。当前版本为 39，旧版和未知版均拒绝，不提供迁移读写。

OBJS v31 在 SRP 的 Earth/Moon 阴影布尔值之后、Cr 之前保存 `boundary_mitigation` u8（0/1）。禁用 SRP、无阴影、未分配遮挡体或零光压力时仍保存草稿，但有效计算身份忽略此开关。当前项目只接受 v40，不解码 v38 或更早布局。

## VOP 插值引力常数

OBJS v31 在插值方法、阶数之后保存独立 `vop_mu` f64，再写固定输出开关。所有方法均验证 μ 为有限正值并保存草稿；只有 VOP 方法将 μ 纳入活动计算身份。它不替代底场 GM，也不切换积分方程。未知枚举、非法阶数或 μ 即使 CRC 正确也拒绝；非当前项目格式不解码。
